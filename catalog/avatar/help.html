Avatars /avatar

Live2D avatars your AI drives through the API — a lighter VTube Studio without face tracking: the bot is the tracker. Any number of avatars, each a named slot (main, guest …) showing a model from the library; the name is what the bot uses. Between commands each avatar keeps itself alive (blinking, breathing, sway, wandering eyes, head motion while talking), through the model's own mappings (its VTube Studio setup, or VTube Studio's defaults).

Setting up

Open the Avatars tab, accept Live2D's license (Hexcast then downloads Live2D's Cubism Core and the renderer once, into config/avatar_runtime/), add a model (a zip, a folder, or straight from VTube Studio if it is installed) and press + Avatar. In OBS add a Browser source, 1920×1080, with Control audio via OBS ticked:

http://localhost:4747/avatar/overlay                 the avatars on the main overlay (all, to begin with)
http://localhost:4747/avatar/overlay/guest           another overlay: its own source, its own avatars
http://localhost:4747/avatar/overlay?avatar=main     only some of an overlay's avatars (?avatar=main,guest)
http://localhost:4747/avatar/overlay?audio=0         silent (another source plays the speech)

Overlays

OBS scales, crops and moves a source as a whole, so avatars that share one source move and scale together. An overlay is one source: press + Overlay above the preview, name it, and put avatars on it (+ Avatar adds to the overlay you are looking at; an existing avatar moves with Overlay on its Placement tab). Add each overlay's URL to OBS as its own Browser source and size, crop and place it there without touching the others. An avatar's position inside its overlay is set by dragging in the preview; where overlays sit relative to each other is up to OBS. Deleting an overlay moves its avatars to main. The API addresses avatars by name, wherever they are.

The tab

The live preview is the OBS renderer itself: drag an avatar to move it, scroll to zoom, drag the dot to rotate, double-click to reset, Shift to snap; items drag and scroll the same way. The inspector has Placement, Face & Mood (emotions, expressions, motions, gestures, a look-at pad, the emotion table), Mouth (lipsync source, meters, tuning, "learn this voice"), Idle, Parameters (every parameter live — drag one to take it over — and the mappings), Items (add, place, lock, pin to the model, and the model's pin points), Clips (Soundboard GIFs locked to the avatar), Colors, Light and API (ready-made calls for that avatar).

Pin points, and gluing things to a model

A pin point is a named spot on a model's art (head_top, left_hand): on the Items tab type a name, press Pick on the model and click the spot. It is saved on the model. Glue things to it by name and they move with that part of the art, not just with the model: an item (its Pin point menu; Lock keeps it from being dragged by accident); another avatar on the same overlay — Placement → Hang from another avatar, a mini model on a head, which rides the head as it turns and nods (drag it in the preview to glue it somewhere else; Let go frees it where it stands); and a Soundboard GIF or video — the Clips tab, Lock to the avatar. A locked clip plays on the overlay that shows the avatar, for anything that plays it (a bot, a hotkey, a redeem), and its sound comes out of that overlay's OBS source. If no open overlay shows the avatar it plays where the Soundboard puts it, and the play call says "attached": false.

PNGtubers

An avatar can be a PNGtuber instead: simple (pictures for quiet / talking / blinking / talking + blinking per state, optional half-open and per-vowel mouths - made from pictures with New PNGtuber from pictures) or layered (PNGTuber Plus style: import its .save). Its PNGtuber tab sets the faces (click a slot or drop a picture on it), the voice (the mouth opens and closes with each word, with a live meter and a built-in test voice) and the movement (a hop when talking starts and a small bounce on each word as the audio comes in; breathing). The API is the same: speech and MouthOpen make it talk, expression / emotion switch its state (one at a time), gesture / look move it, parts shows / hides layers; motion is for Live2D only.

Mouth

Per avatar: speech sent to Hexcast (the speak call — the OBS overlay plays it and lip-syncs from the very samples it plays), an audio device (a mic, a virtual cable or a loopback — Hexcast records it and streams it to the overlays), or nothing (the bot moves the mouth with params / face). The analysis gives VTube Studio's advanced-lipsync inputs (VoiceA … VoiceO, VoiceVolume, VoiceSilence, VoiceFrequency) plus MouthOpen and a mouth form for any model.

Files

Models in media/avatars/models/, items in media/avatars/items/, settings in config/avatar.json. Full guide: docs/avatar.md.

Avatars API /avatar/api

Every call takes the avatar's name (* = all of them); JSON bodies; times in seconds; errors are {"ok": false, "error": …} with a 4xx status. GET /avatar/api lists it all. Each command is POST /avatar/api/avatars/<name>/<command>:

params{"values": {"ParamMouthOpenY": 0.8, "MouthSmile": 1}, "weight": 1, "duration": 0.3, "for": 2, "hold": true, "mode": "set|add", "layer": "input|final"} — any Live2D parameter, or a tracker input (VTube Studio's names, or a custom input that one of the model's mappings takes - see custom_inputs in /info - through the model's mappings; a mapping wins over a parameter of the same id); held until released unless for / "hold": false. Streamed params show in Activity as one line every few seconds
release{"ids": ["ParamMouthOpenY"], "fade": 0.3} — {} releases everything
expression{"name": "Smile", "state": "on|off|toggle", "for": 5} — several can be on at once; several in one call: {"names": ["Smile", "Blush"]}, "only": true switches the others off
parts · release_parts{"values": {"PartArmA": 0, "PartArmB": 1}} — show / hide whole parts (a second arm set, a prop …), held until release_parts
colors · release_colors{"parts": {"PartHair": {"multiply": "#ff8800", "overlay": "#202040", "alpha": 0.9}}, "meshes": {"ArtMesh12": {"alpha": 0}}, "all": {"multiply": "#aabbcc"}, "fade": 0.3, "for": 10, "save": false} — VTube Studio's multiply / screen ("overlay") colours and alpha for parts, art meshes (/info lists them) and the whole model; multiply darkens / tints, overlay lightens, alpha 0 hides; null lets a field go back. Held until release_colors ({"parts": […], "meshes": […], "all": true}, {} = all) or for; "save": true keeps it
color_preset · clear_color_presets{"name": "Night", "state": "on|off|toggle", "for": 20} or {"names": […], "only": true} — a colour preset saved on the avatar's model (the Colors tab; color_presets in /info): a VTube Studio colour hotkey. Several can be on, each over the ones before

Reading and managing

GET /avatar/api/statusOBS sources connected (also by_overlay), avatars, fps and cost per avatar
GET /avatar/api/overlayseach overlay: id, OBS path, its avatars, OBS sources connected · POST {"name": "guest"} makes one, POST …/<name>/delete removes it (its avatars go to main)
GET /avatar/api/avatarssettings + live state of every avatar
GET /avatar/api/avatars/<name>/infothe model's parameters (with ranges and names), parts, art meshes, expressions, motions, emotions, inputs (VTube Studio's, then the model's custom ones - also custom_inputs), mappings
GET /avatar/api/avatars/<name>/params/liveevery parameter's value right now
POST /avatar/api/avatars{"name": "guest", "model": "akari", "overlay": "guest"} — create; POST …/<name> changes settings ({"overlay": "main"} moves it to another overlay), …/rename, …/delete
GET /avatar/api/models · /itemsthe library; POST …/upload (zip or folder), POST …/import {"path": …}
GET /avatar/api/models/<id>/anchorsthe model's pin points · POST {"name": "head_top", "pin": {…}} saves one (the tab makes the pin), POST …/<name>/delete
Soundboard: locking a clipGET /api/play/video/<clip>?avatar=hex&anchor=head_top&dy=-40&ascale=0.8 plays it glued to that avatar (?avatar= empty: on the Soundboard overlay); POST /attach {"file": "heart.mp4", "kind": "video", "attach": {"avatar": "hex", "anchor": "head_top", "dy": -40}} locks it for good (null lets go)

WebSocket

ws://localhost:4747/avatar/ws/control takes the same commands as JSON ({"cmd": "params", "avatar": "main", "values": {…}, "rid": 1}) — for values every frame — and sends events: speech_start, speech_end, speech_error, motion_start, motion_end, loaded, error.

curl -X POST "http://localhost:4747/avatar/api/avatars/main/speak?wait=1" -F "audio=@line.wav"
curl -X POST http://localhost:4747/avatar/api/avatars/main/emotion -H "Content-Type: application/json" -d "{\"name\":\"happy\",\"for\":5}"
curl -X POST http://localhost:4747/avatar/api/avatars/main/params -H "Content-Type: application/json" -d "{\"values\":{\"ParamAngleX\":20},\"duration\":0.5,\"for\":3}"
