Ticker /ticker

A news-style scrolling ticker overlay (/ticker/overlay, 1920×1080) that you place anywhere with the panel's drag box. What scrolls is a list of feeds. Each feed is a named list of lines led by its label badge, and feeds scroll in order. A line with a key is unique in its feed, so writing the same key again updates it in place, which suits things like everyone's hexcoin balance. The overlay takes the next line from the live list as each one scrolls off, so changes land mid-scroll. New lines jump the queue. Every call below works as a GET with query parameters or as a POST with JSON. Details: docs/ticker.md.

GET|POST /ticker/api/say?text=…&ttl=60one-off line in the announce feed. It scrolls next and is gone after ttl seconds (default: the announce feed's ttl, else 60; 0 keeps it). Optional color.
GET|POST /ticker/api/feed/{name}/addtext, or key and/or value; optional color, ttl, first=1. With a key it upserts. Creates the feed if it's new.
GET|POST /ticker/api/feed/{name}/setsame as add, e.g. ?key=alice&value=1300
POST /ticker/api/feed/{name}create or update a feed. Settings you send change; the rest are kept: label, template ({key} {value} {text}), sort (none|value_desc|value_asc|key|newest), limit, ttl (seconds each new line lasts; 0 = forever, and a line's own ttl wins), color, enabled, source. items (strings or objects) or values ({"alice":1300}) replaces the lines.
GET|POST /ticker/api/feed/{name}/removeby id, key or exact text
GET|POST /ticker/api/feed/{name}/clear · enable?on=0|1 · refresh · deleteempty it · take it on/off air · poll its URL source now · remove it
GET /ticker/api/feed/{name} · /ticker/api/feedsone feed or every feed, with each feed's rendered lines
POST /ticker/api/feeds/order{"order": ["announce","balances","news"]}
GET /ticker/api/itemsexactly what is scrolling right now
GET|POST /ticker/api/show · hideshow or hide the whole ticker
GET /ticker/api/statusoverlays connected, visible, feed and line counts
GET|POST /ticker/api/configstyle: merge-and-save any subset of keys

A feed can also pull its lines from a JSON URL on a timer. The URL can return a list of strings, a list of objects, or a {"key": value} object, and path, key_field and value_field pick what to read. Or write config/ticker_feeds.json directly; it's reloaded within a second.

curl "http://localhost:4747/ticker/api/feed/balances/set?key=alice&value=1300"
curl -X POST http://localhost:4747/ticker/api/feed/balances -H "Content-Type: application/json" -d "{\"label\":\"HEXBANK\",\"sort\":\"value_desc\",\"limit\":20,\"values\":{\"alice\":1300,\"bob\":250}}"
curl "http://localhost:4747/ticker/api/say?text=Raffle%20closes%20soon&ttl=90"
