Music /ytm

Now-playing overlay with two sources, chosen with Music source on the panel: the YouTube Music Desktop App (via its companion server), or local files from a mapped folder played through the overlay itself (OBS captures the audio).

GET /ytm/api/nowplayingone plain-text line: Title - Artist (Album) — made for a chat bot's !song (reflects the active source)
GET /ytm/api/nowplaying.jsonthe full state as JSON
GET /ytm/api/statusconnection + pairing state
POST /ytm/api/command{"command": "next"} — routed to whichever source is active

YouTube Music commands

playPause, play, pause, next, previous, volumeUp, volumeDown, setVolume (0–100), mute, unmute, seekTo, shuffle, repeatMode, toggleLike, toggleDislike, playQueueIndex, changeVideo — so a channel-point redeem can skip a track.

A Forward URL on the panel POSTs the full state on every track change, and Clip on track change fires a soundboard clip by name through /api/play/{name}.

Local files

On the Local library tab: pick a folder (Browse… uses an in-panel file browser that works from any device), then browse/search and build a queue. Add this folder (+ subfolders) queues thousands at once server-side; the queue list is virtualised so huge queues stay smooth. Save a queue as a playlist (JSON) and load/append it later. ▸ previews a track in the panel only (not the stream). The visualiser reacts to the real audio via Web Audio in the overlay. Transport uses the same /ytm/api/command.

GET /ytm/library/statusindex progress (root, count, ready/indexing)
GET /ytm/library/browse?path= · search?q=one folder level · filename/folder search
GET /ytm/fs/list?path=host drives/folders, for the folder picker
GET /ytm/queue/state · items?offset=&limit=lightweight state · a window of items
POST /ytm/queue/add|add-folder|remove|move|clear|playqueue edits
GET /ytm/playlists · POST /ytm/playlists/save|load|rename|deletenamed playlists
