Roulette /games#roulette

A bot-driven roulette wheel overlay (/games/overlay, 1920×1080, Control audio via OBS on for the built-in ball sounds). A spin pops the wheel in, launches the ball, and it bounces and settles in the pocket the server picked with secrets.SystemRandom — uniformly over the 38 pockets of an American double-zero wheel. The overlay only animates that result; nothing can force one. Placement works like the soundboard's Edit Mode. Optional bets sent with a spin come back resolved at standard odds for a bot to pay out — or chat's bets wait on the table for the next spin, shown on an "on the table" board while a spin timer counts down (NEXT SPIN 0:12), and at zero the wheel spins by itself and the winnings go through the ledger craps uses. Launch/landing clips play on the soundboard overlay. {game} is roulette here (each game has its own help page). All endpoints return {"ok": true/false, ...}.

Two ways to run the money

Mode A — Hexcast does the math, two routes: send bets with the spin and credit each bet's returned (no ledger), or put the bets on the table with /bet and pay from the ledger (the durable route, like craps) — never the same bet from both. Mode B — your bot does the math (here that's Hex, whose own code keeps everyone's coins in its hexbank): keep the bets in the bot, spin with wait=true and no bets (or start the /timer and show the bets with /board), work out the payouts from result, pay from the hexbank, then POST /announce the winners with the spin's id as spin_id. Either way the pocket is Hexcast's fair spin — a bot can't send a result, and announce and board only change what the screen says (never the result, bets, ledger, history or stats).

Announce fields (query or JSON body — body wins)

"lines": [{user, amount, text}]up to 50 kept; each needs a user or a text (unusable lines are skipped); [] = nobody won. user ≤ 40 chars, cleaned like a spin's user (leading @ dropped); text ≤ 60; amount optional, any finite number up to ±1e12 — shown +200 green, −50 red, 0 dim. Query shorthand for one line: ?user=alice&amount=200&text=Red
title · empty_text≤ 40 chars, default WINNERS · ≤ 60 chars, default No winners (shown when there are no lines)
currency≤ 24 chars, shown after each amount; default the game's currency setting (hexcoins unless changed); "" for none
seconds1–120; default the rest of the result phase, or result seconds when the game isn't spinning or in result. Posted while the ball is in the air, it counts from the landing. The game stays on screen that long (unless hidden or stopped)
spin_idthe current spin (in the air / showing its result), or the last committed one when there's none — also the default without it; any other id → 409 stale

Reply: {"ok": true, "announce": {id, spin_id, title, lines, empty_text, currency, expires_in_ms}, "state": {...}}. Every game's state carries the card as announce (null when none); the server takes it down when seconds run out, and a new spin clears it.

Bet syntax (case-insensitive, net odds "X to 1")

17 · 0 · 00straight — 35
split:17-20 · 17/20split — 17; two numbers touching on the table, plus zero splits 0/1 0/2 00/2 00/3 0/00
street:13 · 13/14/15street — 11
0/1/2 · 0/00/2 · 00/2/3trio — 11 (also with a trio: prefix)
corner:17 · 17/18/20/21corner — 8 (lowest number of a 2×2 block, not in column 3 or the last row)
basket · 0/00/1/2/3basket — 6 (also topline, five); there is no first-four bet
line:13 · line:13-18six line — 5 (also sixline:13 or the six bare numbers)
d1 · 2nd12 · 25-36dozen — 2 (also dozen1, 1st12, 1-12, …)
col1 · col2 · col3column — 2 (also column1, c1)
red · black · odd · even · low · higheven money — 1 (lose on 0 and 00); also r, b, 1-18, 19-36, manque, passe

Each bet comes back with valid, type, label, numbers, odds, win, payout (net: win amount × odds, loss -amount) and returned (win amount × (odds + 1), loss 0). Invalid bets never block the spin: valid: false with an error and the stake as returned — except a bad amount (negative, not a number, over 1e12), which comes back as 0. Hexcast keeps no balances — your bot credits returned. Full guide, config keys and bot recipes: docs/games.md.

Table & spin timer (hexcoins)

The durable Mode A route, the same as craps': bets wait on Hexcast's table, one-spin bets that can come down until the ball is thrown; bets are closed only while it's in the air (409 bets_closed). The countdown: with auto-spin on (auto_spin), the first bet starts a bet window countdown (bet_window_seconds, default 20), and it starts again after each spin while bets are down; /timer starts one any time, even with no bets. At zero the wheel spins like a /spin with every bet on the table. Any spin (test ones too), Stop, /timer/cancel and /clear stop either kind; the last bet coming down or auto-spin switched off stop only auto-spin's. While a countdown runs, the wheel stays on screen (unless hidden). At the landing each winning bet gets one ledger credit win (stake + winnings, roll_id = the spin's id) and every bet leaves the table; losers have no event (the stake was the debit). A restart in mid-air cancels that spin — the bets ride on the next; test spins never touch the table.

Hex's side (Mode A, table): check the viewer's hexbank balance → POST /bet → debit each debits[] entry and mark its seq done (a failed debit: /remove that bet_id). Start rounds with /timer (or auto-spin). Pay by tailing /games/api/ledger?since=<last applied seq> — every game in one tail — applying each event once in seq order (credits win, remove, refund; debits Hex didn't take itself, like a bet from the panel), saving that seq together with the hexbank change. Announce from /roulette/last (result, credits), never pay from it. Mode B with the timer: Hex keeps its bets → POST /timer → POST /board after every bet → close bets at zero (or as soon as a spin starts) → wait for a new spin id on /roulette/last → settle from its result → POST /announce and an empty /board. Recipes and sample code: docs/games.md → Table & spin timer.

Hooking up the bank (Hex's hexbank, Mode A, bets on the spin call): collect bets in Hex's own betting window, check each bet's text with /validate and its amount in Hex (a positive whole number ≤ 1e12), debit the stake, spin once with "bets": [{user, bet, amount}] and wait=true, then credit every bet's returned. 409 busy: nothing spun, keep the stakes and retry after retry_in_ms; a Stop mid-spin still commits it, so pay as normal; test spins never count. This route has no ledger — mark each spin id + bet index paid, and pay from the reply promptly: /history (each spin with its resolved bets) is memory only, the last 200, emptied on restart. Step by step: docs/games.md → Hooking up the bank.
