Countdown /countdown

Styleable countdown timer overlay — count down a fixed duration or to a clock time. The server owns the remaining time and streams it to the overlay, so clock skew never matters. Media cues can fire any number of soundboard clips, each anchored to its own countdown threshold — set a clip to end at a point (e.g. intro music finishing exactly at 0:00, timed backwards from the clip's length) or to start at a point. Clips play on the soundboard overlay, honouring their saved trim/volume/cooldown, so keep both browser sources in the scene.

GET /countdown/api/statusconnected overlay count + timer snapshot
GET /countdown/api/configfull config as JSON
POST /countdown/api/configmerge-and-save any subset of config keys
POST /countdown/api/timer{"action": "start"} — also pause, resume, reset; start accepts an optional "seconds" for an ad-hoc duration

Media cues config

Posted as a media_cues array (replaces the whole list). Each entry: enabled (bool), kind (audio | video), name (clip name), anchor (end = clip finishes at the threshold, timed backwards from its length; start = clip fires at the threshold), offset (seconds remaining at the threshold; 0 = at zero). Read when the timer starts — pause cancels pending cues, resume re-arms them. The legacy single-cue keys (media_enabled/media_kind/media_name/media_end_offset) are still migrated automatically.

curl -X POST http://localhost:4747/countdown/api/timer -H "Content-Type: application/json" -d "{\"action\":\"start\",\"seconds\":90}"
curl -X POST http://localhost:4747/countdown/api/config -H "Content-Type: application/json" -d "{\"media_cues\":[{\"enabled\":true,\"kind\":\"audio\",\"name\":\"intro\",\"anchor\":\"end\",\"offset\":0}]}"
