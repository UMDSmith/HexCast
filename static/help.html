Soundboard core

Trigger media from your library by name — everything a bot, hotkey deck, or channel-point redeem needs is a single GET. Names are the filename without extension, case-insensitive. The overlay applies each clip's saved position, scale, volume, trim and chroma key automatically; query params override them for one play. Chroma keying (Edit Mode → clip → Chroma key: color, 💧 eyedropper, tolerance) removes the green screen per clip inside the overlay, so overlapping clips composite cleanly — drop any chroma filter on the OBS source itself.

GET /api/listevery triggerable name, grouped audio / video
GET /api/play/{name}play by name across both kinds (audio checked first)
GET /api/play/{kind}/{name}same, but explicit — kind is audio or video
GET /api/stopclear all overlay visuals and stop all audio
GET /apithis reference as JSON

Per-play overrides (query params)

?x=50&y=50&scale=2position/size, video only (percent of canvas, scale factor)
?volume=0.50.0–1.0, audio and video-with-audio
?start=2&end=5trim window in seconds (static images use it as display time)
curl http://localhost:4747/api/play/airhorn
curl "http://localhost:4747/api/play/video/cheer?x=80&y=20&scale=2&end=3"
curl http://localhost:4747/api/stop

Clips /clips

A hand-fired queue of Twitch clips/VODs, YouTube videos, or any single yt-dlp-supported URL. Nothing auto-advances. Everything streams from the source unless pre-download is enabled. {ref} is a #number, item id, exact clip slug, or next (first still-queued item). All endpoints return {"ok": true/false, ...}.

Auto-level clip volume (Settings tab) measures each clip's loudness on the server with ffmpeg (nothing downloaded) and turns louder clips down so clips and !so shoutouts arrive at a consistent volume (target default -16 LUFS). It normalises toward the target — quieter clips are left alone, iframe fallbacks use master volume only.

GET /clips/api/queuefull queue + player state as JSON
GET /clips/api/add?url=...add a URL (returns the entry incl. its number); POST {"text": "..."} to extract every link from a blob
GET /clips/api/play/{ref}play an item
GET /clips/api/pause · resume · toggle · stoptransport; Stop clears the overlay without marking the item played
GET /clips/api/statusplayer state, current item, queue counts
GET /clips/api/remove/{ref}remove an item (also DELETE /clips/api/queue/{ref})
POST /clips/api/reset_numbersrenumber the queue 1..N and restart the counter
GET /clips/api/shoutout/{channel}?count=2play random clips from a Twitch channel back to back, ephemerally (never queued or saved)

Numbers are never reused, so a bot's !playclip 7 can't fire the wrong thing after removals — that's why the counter only climbs until you reset it. Played items dim but stay listed until Clear played on the Queue tab.

curl "http://localhost:4747/clips/api/add?url=https://clips.twitch.tv/SomeSlug"
curl http://localhost:4747/clips/api/play/7
curl http://localhost:4747/clips/api/play/next

Feeding a bot

Set Forward URL on the Connection tab and every chat message and alert is POSTed there as JSON — {"type": "chat", "user": {...}, "flags": {"mod": true, ...}, "text": "..."} for chat, {"type": "event", "kind": "raid", ...} for alerts.

Shoutouts !so

You or a mod types !so channelname (or @channelname) in your own chat, and three things happen:

1 — official shoutoutthe real Twitch /shoutout banner (Twitch only accepts these while you're live)
2 — chat lineposted from your account; template configurable with {name}, {login}, {url}
3 — their clipstwo random clips from their channel play back to back on the Clips overlay — ephemeral, nothing queued or saved. Stop, or manually playing anything, cancels the rest

The chat-side parts need the moderator:manage:shoutouts and user:write:chat scopes — if you signed in before those existed, reconnect once in the Twitch panel. Without any sign-in the clips still play; only the chat messages are skipped (the Twitch panel log says exactly which piece did what).

Settings: config/twitch.json → "shoutout" — on, command (default !so), who (mods or broadcaster), native, message, clip, clip_count (1–5). Dry-run with !so somechannel in the Twitch panel's test-chat box, or call GET /clips/api/shoutout/{channel} directly.

Any saved layout setting can be overridden per browser source: layout (row/column/grid/free), grid_columns, size, spacing, align, show_names, name_size, name_color, shape, dim, dim_pairs, desaturate, bounce, hide_muted, mute_badge — booleans take 0/1, e.g. /discord/overlay?layout=column&size=96&show_names=0.

Countdown /countdown

Styleable countdown timer overlay — count down a fixed duration or to a clock time. The server owns the remaining time and streams it to the overlay, so clock skew never matters. Media cues can fire any number of soundboard clips, each anchored to its own countdown threshold — set a clip to end at a point (e.g. intro music finishing exactly at 0:00, timed backwards from the clip's length) or to start at a point. Clips play on the soundboard overlay, honouring their saved trim/volume/cooldown, so keep both browser sources in the scene.

GET /countdown/api/statusconnected overlay count + timer snapshot
GET /countdown/api/configfull config as JSON
POST /countdown/api/configmerge-and-save any subset of config keys
POST /countdown/api/timer{"action": "start"} — also pause, resume, reset; start accepts an optional "seconds" for an ad-hoc duration

Media cues config

Posted as a media_cues array (replaces the whole list). Each entry: enabled (bool), kind (audio | video), name (clip name), anchor (end = clip finishes at the threshold, timed backwards from its length; start = clip fires at the threshold), offset (seconds remaining at the threshold; 0 = at zero). Read when the timer starts — pause cancels pending cues, resume re-arms them. The legacy single-cue keys (media_enabled/media_kind/media_name/media_end_offset) are still migrated automatically.

curl -X POST http://localhost:4747/countdown/api/timer -H "Content-Type: application/json" -d "{\"action\":\"start\",\"seconds\":90}"
curl -X POST http://localhost:4747/countdown/api/config -H "Content-Type: application/json" -d "{\"media_cues\":[{\"enabled\":true,\"kind\":\"audio\",\"name\":\"intro\",\"anchor\":\"end\",\"offset\":0}]}"

Games /games

A bot-driven roulette wheel overlay (/games/overlay, 1920×1080, Control audio via OBS on for the built-in ball sounds). A spin pops the wheel in, launches the ball, and it bounces and settles in the pocket the server picked with secrets.SystemRandom — uniformly over the 38 pockets of an American double-zero wheel. The overlay only animates that result; nothing can force one. Placement works like the soundboard's Edit Mode. Optional bets sent with a spin come back resolved at standard odds for a bot to pay out — or chat's bets wait on the table for the next spin, shown on an "on the table" board while a spin timer counts down (NEXT SPIN 0:12), and at zero the wheel spins by itself and the winnings go through the ledger craps uses. Launch/landing clips play on the soundboard overlay. {game} is roulette here (Craps has its own card below). All endpoints return {"ok": true/false, ...}.

GET|POST /games/api/roulette/spinstart a spin (alias /play) — returns the result, resolved bets and lands_at, plus the table's settlements, credits, table_summary and table (+ the spin's ledger events with wait); 409 {"error": "busy", "retry_in_ms", "state"} while a spin is spinning, showing its result, or in cooldown
GET|POST /games/api/roulette/beton the table for the next spin: {user, bet, amount} or {"bets": [...]} (up to 200; whole coins, min_bet, max_bet per bet line; the same user + bet adds to that line) → accepted (with action new / add), rejected (each with an error), debits [{user, amount, bet_id, seq, reason}], table. 200 if any were accepted, 400 if all were rejected, 409 bets_closed while the ball is in the air
GET|POST /games/api/roulette/remove{bet_id} · {user, bet} · {user, all: true} → removed (each with its refund), credits, ledger (reason remove), table; 400 when nothing matches, 409 bets_closed while the ball is in the air
GET /games/api/roulette/tableevery bet (id, user, bet, label, type, numbers, odds, amount, pays), exposure per user, total_on_table, bets_open, auto_spin_in_ms (the countdown, null when none), last_seq, display_board
GET /games/api/roulette/user/{name}one viewer's table bets, exposure and roulette session debits / credits / net
GET|POST /games/api/roulette/clearrefund every table bet (reason refund) and stop the countdown; 409 bets_closed while the ball is in the air
GET|POST /games/api/roulette/timerstart (or restart) the countdown now: seconds 5–300 (default bet window), with or without bets, auto-spin on or off; at 0 the wheel spins by itself with everything on the table → {auto_in_ms, table, state}; 409 busy unless idle. The same route works for craps
GET|POST /games/api/roulette/timer/cancelstop any countdown (auto-spin's or the timer's); nothing spins → {cancelled, table, state}
GET /games/api/roulette/ledger?since=0&limit=500roulette's ledger events with seq > since, oldest first (limit up to 5000): debit bet / add, credit win (stake + winnings) / remove / refund; plus last_seq (of every game — gaps are craps events), oldest_seq and truncated
GET /games/api/ledger?since=0&game=the shared ledger: every game's events in one stream, each with its game; game=roulette or craps for one
GET|POST /games/api/roulette/board · board/clearMode B: Hex's own "on the table" board before the spin — {title, bets: [{user, text, amount}]}, the same fields as craps' board (below) — shown instead of the table's bets (up to table lines; show table applies); returns {table} with it as display_board. Memory only, allowed while the ball flies; never touches bets or the ledger
GET /games/api/roulette/lastlast committed spin and its result
GET|POST /games/api/roulette/announcedisplay only, for a bot that did its own math (Mode B): a winners card for the current or last spin — {title, lines: [{user, amount, text}], empty_text, seconds, spin_id, currency} — that replaces the computed winners list (up to bets max lines; show bets applies); held until the ball lands. 409 {"error": "stale", "spin_id"} when spin_id isn't the current (or last) spin; 400 on bad JSON, when lines isn't a list, or when no usable line and no empty_text was sent ("lines": [] alone is fine — it shows No winners)
GET|POST /games/api/roulette/announce/cleartake the card down now (the next spin clears it too)
GET /games/api/roulette/history?limit=20recent spins (newest first) + stats: colour/odd-even/low-high counts, per-number counts, hot, cold, streak
POST /games/api/roulette/history/clearclear history and stats (GET works too)

GET /games/api/roulette/betsbet-type reference: syntax examples, odds

Two ways to run the money

Mode A — Hexcast does the math, two routes: send bets with the spin and credit each bet's returned (no ledger), or put the bets on the table with /bet and pay from the ledger (the durable route, like craps) — never the same bet from both. Mode B — your bot does the math (here that's Hex, whose own code keeps everyone's coins in its hexbank): keep the bets in the bot, spin with wait=true and no bets (or start the /timer and show the bets with /board), work out the payouts from result, pay from the hexbank, then POST /announce the winners with the spin's id as spin_id. Either way the pocket is Hexcast's fair spin — a bot can't send a result, and announce and board only change what the screen says (never the result, bets, ledger, history or stats).

Announce fields (query or JSON body — body wins)

"lines": [{user, amount, text}]up to 50 kept; each needs a user or a text (unusable lines are skipped); [] = nobody won. user ≤ 40 chars, cleaned like a spin's user (leading @ dropped); text ≤ 60; amount optional, any finite number up to ±1e12 — shown +200 green, −50 red, 0 dim. Query shorthand for one line: ?user=alice&amount=200&text=Red
title · empty_text≤ 40 chars, default WINNERS · ≤ 60 chars, default No winners (shown when there are no lines)
currency≤ 24 chars, shown after each amount; default the game's currency setting (hexcoins unless changed); "" for none
seconds1–120; default the rest of the result phase, or result seconds when the game isn't spinning or in result. Posted while the ball is in the air, it counts from the landing. The game stays on screen that long (unless hidden or stopped)
spin_idthe current spin (in the air / showing its result), or the last committed one when there's none — also the default without it; any other id → 409 stale

Reply: {"ok": true, "announce": {id, spin_id, title, lines, empty_text, currency, expires_in_ms}, "state": {...}}. Every game's state carries the card as announce (null when none); the server takes it down when seconds run out, and a new spin clears it.

Bet syntax (case-insensitive, net odds "X to 1")

17 · 0 · 00straight — 35
split:17-20 · 17/20split — 17; two numbers touching on the table, plus zero splits 0/1 0/2 00/2 00/3 0/00
street:13 · 13/14/15street — 11
0/1/2 · 0/00/2 · 00/2/3trio — 11 (also with a trio: prefix)
corner:17 · 17/18/20/21corner — 8 (lowest number of a 2×2 block, not in column 3 or the last row)
basket · 0/00/1/2/3basket — 6 (also topline, five); there is no first-four bet
line:13 · line:13-18six line — 5 (also sixline:13 or the six bare numbers)
d1 · 2nd12 · 25-36dozen — 2 (also dozen1, 1st12, 1-12, …)
col1 · col2 · col3column — 2 (also column1, c1)
red · black · odd · even · low · higheven money — 1 (lose on 0 and 00); also r, b, 1-18, 19-36, manque, passe

Each bet comes back with valid, type, label, numbers, odds, win, payout (net: win amount × odds, loss -amount) and returned (win amount × (odds + 1), loss 0). Invalid bets never block the spin: valid: false with an error and the stake as returned — except a bad amount (negative, not a number, over 1e12), which comes back as 0. Hexcast keeps no balances — your bot credits returned. Full guide, config keys and bot recipes: docs/games.md.

Table & spin timer (hexcoins)

The durable Mode A route, the same as craps': bets wait on Hexcast's table, one-spin bets that can come down until the ball is thrown; bets are closed only while it's in the air (409 bets_closed). The countdown: with auto-spin on (auto_spin), the first bet starts a bet window countdown (bet_window_seconds, default 20), and it starts again after each spin while bets are down; /timer starts one any time, even with no bets. At zero the wheel spins like a /spin with every bet on the table. Any spin (test ones too), Stop, /timer/cancel and /clear stop either kind; the last bet coming down or auto-spin switched off stop only auto-spin's. While a countdown runs, the wheel stays on screen (unless hidden). At the landing each winning bet gets one ledger credit win (stake + winnings, roll_id = the spin's id) and every bet leaves the table; losers have no event (the stake was the debit). A restart in mid-air cancels that spin — the bets ride on the next; test spins never touch the table.

Hex's side (Mode A, table): check the viewer's hexbank balance → POST /bet → debit each debits[] entry and mark its seq done (a failed debit: /remove that bet_id). Start rounds with /timer (or auto-spin). Pay by tailing /games/api/ledger?since=<last applied seq> — every game in one tail — applying each event once in seq order (credits win, remove, refund; debits Hex didn't take itself, like a bet from the panel), saving that seq together with the hexbank change. Announce from /roulette/last (result, credits), never pay from it. Mode B with the timer: Hex keeps its bets → POST /timer → POST /board after every bet → close bets at zero (or as soon as a spin starts) → wait for a new spin id on /roulette/last → settle from its result → POST /announce and an empty /board. Recipes and sample code: docs/games.md → Table & spin timer.

Hooking up the bank (Hex's hexbank, Mode A, bets on the spin call): collect bets in Hex's own betting window, check each bet's text with /validate and its amount in Hex (a positive whole number ≤ 1e12), debit the stake, spin once with "bets": [{user, bet, amount}] and wait=true, then credit every bet's returned. 409 busy: nothing spun, keep the stakes and retry after retry_in_ms; a Stop mid-spin still commits it, so pay as normal; test spins never count. This route has no ledger — mark each spin id + bet index paid, and pay from the reply promptly: /history (each spin with its resolved bets) is memory only, the last 200, emptied on restart. Step by step: docs/games.md → Hooking up the bank.

Craps /games#craps

A bank-craps table on the games overlay (/games/overlay, or ?game=craps for its own source). Chat bets hexcoins; bets stay on the table across rolls like a casino. The server rolls two dice with secrets.SystemRandom, the overlay throws them onto exactly those faces, the stickman calls it, the puck moves and every bet settles by standard casino rules. Nothing can force the dice. Hexcast holds no balances: the bank is Hex, whose hexbank takes the coins for every debit and pays every credit in a numbered, persisted ledger — or Hex does the math itself and only tells the overlay what to show (Mode B, below). All endpoints return {"ok": true/false, ...}.

GET|POST /games/api/craps/rollthrow the dice (aliases /spin, /play) — returns the dice, settlements (every bet with action), credits per user, summary, table (+ the roll's ledger events with wait); 409 {"error": "busy", "retry_in_ms", "state"} while a roll is in the air, showing its result, or in cooldown
GET|POST /games/api/craps/bet{user, bet, amount, target?} or {"bets": [...]} (up to 200) → accepted, rejected (each with an error), debits [{user, amount, bet_id, seq}], table. 200 if any were accepted, 400 if all were rejected, 409 bets_closed while the dice are in the air
GET|POST /games/api/craps/remove{bet_id} · {user, bet} ("bet": "odds" takes down just the odds) · {user, all: true} → removed, credits (refunds), ledger; contract bets answer 400, 409 bets_closed while the dice are in the air
GET /games/api/craps/tablephase, point, shooter, hand rolls, every bet, exposure per user, bets_open, auto_roll_in_ms (the countdown — auto-roll or /timer), last_seq
GET /games/api/craps/user/{name}one viewer's bets, exposure and craps session debits / credits / net
GET /games/api/craps/ledger?since=0&limit=500craps' ledger events with seq > since, oldest first (limit up to 5000), plus last_seq, oldest_seq and truncated (the limit cut it, or older events are only in config/games_ledger.jsonl). The ledger is shared with roulette's table (one seq numbering, each event names its game), so gaps are normal; GET /games/api/ledger has every game's
GET|POST /games/api/craps/clearrefund every bet (reason refund), back to a come-out, shooter cleared, countdown stopped; 409 bets_closed while the dice are in the air
GET|POST /games/api/craps/timer · timer/cancelthe roll timer: start (or restart) a countdown now — seconds 5–300 (default bet window), with or without bets, auto-roll on or off; at 0 the shooter's dice go by themselves → {auto_in_ms, table, state}, 409 busy unless idle · stop any countdown → {cancelled, table, state}. Hooking up the bank (hexcoins)

Placing a bet — either (a) check the viewer's hexbank balance → POST /bet → debit each accepted debits[] entry (if a debit then fails, /remove that bet), or (b) debit first → POST /bet → credit back whatever was rejected. Rejected bets and a 409 move nothing. Paying out — tail /ledger?since=<last applied seq>, apply each event once in seq order, and save that seq in Hex together with the hexbank change, so payouts happen exactly once across restarts of either side. Skip the debits Hex already took from a /bet reply; take any other debit (a bet placed from the panel). The tail also catches panel rolls, auto-rolls and timer rolls, take-downs (remove) and clears (refund); running roulette's table too, tail /games/api/ledger (every game) once instead. The /roll?wait=true reply's credits is for announcing in chat, not for paying. The table and ledger persist in config/; seq keeps counting across restarts, and a restart while the dice are in the air cancels that roll (bets stay, nothing is paid). Winnings round down to whole coins — suggest amounts that pay exactly (place 6/8 in 6s, place 4/5/9/10 in 5s, odds on 6/8 in 5s). Step-by-step guide for Hex's developer, chat-command flow and sample code: docs/craps.md.

Hex does the math (Mode B)

The other way to run the money: Hexcast's table stays empty and Hex keeps the bets in its own code. Take the stake in the hexbank and mirror the bets with POST /board → close bets and POST /roll with wait: true and no bets → settle Hex's bets from result (event, total, dice, phase_before, point_before) → credit the hexbank → POST /announce the payouts with the roll's id as spin_id and post the updated /board. The dice, puck and shooter are still Hexcast's fair roll — Hex can't send dice. Never also /bet those bets (they'd be settled and in the ledger twice); auto-roll only counts bets on Hexcast's table, so Hex rolls — or starts the roll timer (/timer) and reads the roll it throws from /last; re-post the board after a Hexcast restart (it's memory only). Recipe and sample code: docs/craps.md.

Browser notes

Sound in a browser tab

Browsers block unmuted autoplay in normal tabs until you've interacted with the page. If a clip starts silent, the overlay shows a "muted by the browser" pill — one click anywhere fixes the whole tab session. Permanent fix: Firefox — address-bar permissions icon → Autoplay → Allow Audio and Video. Chrome — padlock → Site settings → Sound → Allow (Chrome also learns from regular use). Permissions apply to the whole host and port, every page under it. OBS browser sources allow unmuted autoplay natively and are never affected.

OBS browser sources

For every overlay: uncheck Shutdown source when not visible and Refresh browser when scene becomes active. Overlays reconnect on their own and restyle live when you save settings in a panel. If a re-upload doesn't repaint, right-click the source → Interact → Ctrl+Shift+R.

No authentication

Every endpoint above is open to anyone who can reach the port — that's what makes bots one-line simple. Keep HexCast on a trusted LAN and never expose it to the internet.
