Soundboard core

Trigger media from your library by name — everything a bot, hotkey deck, or channel-point redeem needs is a single GET. Names are the filename without extension, case-insensitive. The overlay applies each clip's saved position, scale, volume and trim automatically; query params override them for one play.

GET /api/listevery triggerable name, grouped audio / video
GET /api/play/{name}play by name across both kinds (audio checked first)
GET /api/play/{kind}/{name}same, but explicit — kind is audio or video
GET /api/stopclear all overlay visuals and stop all audio
GET /apithis reference as JSON

Per-play overrides (query params)

?x=50&y=50&scale=2position/size, video only (percent of canvas, scale factor)
?volume=0.50.0–1.0, audio and video-with-audio
?start=2&end=5trim window in seconds (static images use it as display time)
curl http://localhost:4747/api/play/airhorn
curl "http://localhost:4747/api/play/video/cheer?x=80&y=20&scale=2&end=3"
curl http://localhost:4747/api/stop

Clips /clips

A hand-fired queue of Twitch clips/VODs, YouTube videos, or any single yt-dlp-supported URL. Nothing auto-advances. Everything streams from the source unless pre-download is enabled. {ref} is a #number, item id, exact clip slug, or next (first still-queued item). All endpoints return {"ok": true/false, ...}.

GET /clips/api/queuefull queue + player state as JSON
GET /clips/api/add?url=...add a URL (returns the entry incl. its number); POST {"text": "..."} to extract every link from a blob
GET /clips/api/play/{ref}play an item
GET /clips/api/pause · resume · toggle · stoptransport; Stop clears the overlay without marking the item played
GET /clips/api/statusplayer state, current item, queue counts
GET /clips/api/remove/{ref}remove an item (also DELETE /clips/api/queue/{ref})
POST /clips/api/reset_numbersrenumber the queue 1..N and restart the counter
GET /clips/api/shoutout/{channel}?count=2play random clips from a Twitch channel back to back, ephemerally (never queued or saved)

Numbers are never reused, so a bot's !playclip 7 can't fire the wrong thing after removals — that's why the counter only climbs until you reset it. Played items dim but stay listed until Clear played on the Queue tab.

curl "http://localhost:4747/clips/api/add?url=https://clips.twitch.tv/SomeSlug"
curl http://localhost:4747/clips/api/play/7
curl http://localhost:4747/clips/api/play/next

Twitch /twitch

Chat overlay, alert overlay with a FIFO queue, and chat-command handling. Alerts can fire any soundboard clip by name — set it in the Clip column of the Alerts table on the Twitch panel.

GET /twitch/api/statusconnection state, signed-in user, granted scopes, log
GET /twitch/api/queuethe alert queue (playing + waiting)
POST /twitch/api/queue/skip · clearskip the current alert / drop the whole queue
POST /twitch/api/test/chat{"text": "..."} — fake a chat line (runs commands like !so as the broadcaster)
POST /twitch/api/test/event{"kind": "follow"} — fire a sample alert

Feeding a bot

Set Forward URL on the Connection tab and every chat message and alert is POSTed there as JSON — {"type": "chat", "user": {...}, "flags": {"mod": true, ...}, "text": "..."} for chat, {"type": "event", "kind": "raid", ...} for alerts.

Shoutouts !so

You or a mod types !so channelname (or @channelname) in your own chat, and three things happen:

1 — official shoutoutthe real Twitch /shoutout banner (Twitch only accepts these while you're live)
2 — chat lineposted from your account; template configurable with {name}, {login}, {url}
3 — their clipstwo random clips from their channel play back to back on the Clips overlay — ephemeral, nothing queued or saved. Stop, or manually playing anything, cancels the rest

The chat-side parts need the moderator:manage:shoutouts and user:write:chat scopes — if you signed in before those existed, reconnect once in the Twitch panel. Without any sign-in the clips still play; only the chat messages are skipped (the Twitch panel log says exactly which piece did what).

Settings: config/twitch.json → "shoutout" — on, command (default !so), who (mods or broadcaster), native, message, clip, clip_count (1–5). Dry-run with !so somechannel in the Twitch panel's test-chat box, or call GET /clips/api/shoutout/{channel} directly.

Music /ytm

Now-playing overlay fed by the YouTube Music Desktop App's companion server.

GET /ytm/api/nowplayingone plain-text line: Title - Artist (Album) — made for a chat bot's !song
GET /ytm/api/nowplaying.jsonthe full state as JSON
GET /ytm/api/statusconnection + pairing state
POST /ytm/api/command{"command": "next"} — proxied to the app

Valid commands

playPause, play, pause, next, previous, volumeUp, volumeDown, setVolume (0–100), mute, unmute, seekTo, shuffle, repeatMode, toggleLike, toggleDislike, playQueueIndex, changeVideo — so a channel-point redeem can skip a track.

A Forward URL on the panel POSTs the full state on every track change, and Clip on track change fires a soundboard clip by name through /api/play/{name}.

Discord /discord

Voice-reactive overlay — everyone in your current voice channel, lighting up as they speak, using Discord avatars or per-person uploaded idle/talking images. Configuration is panel-driven; the useful HTTP surface is small:

GET /discord/api/statusconnection state, current channel, participants
GET /discord/avatar/{user_id}server-cached avatar proxy (what the overlay uses)
POST /discord/api/test/userinject a fake participant / toggle their speaking — style the overlay without being in a call

Overlay query params

Any saved layout setting can be overridden per browser source: layout (row/column/grid/free), grid_columns, size, spacing, align, show_names, name_size, name_color, shape, dim, dim_pairs, desaturate, bounce, hide_muted, mute_badge — booleans take 0/1, e.g. /discord/overlay?layout=column&size=96&show_names=0.

Browser notes

Sound in a browser tab

Browsers block unmuted autoplay in normal tabs until you've interacted with the page. If a clip starts silent, the overlay shows a "muted by the browser" pill — one click anywhere fixes the whole tab session. Permanent fix: Firefox — address-bar permissions icon → Autoplay → Allow Audio and Video. Chrome — padlock → Site settings → Sound → Allow (Chrome also learns from regular use). Permissions apply to the whole host and port, every page under it. OBS browser sources allow unmuted autoplay natively and are never affected.

OBS browser sources

For every overlay: uncheck Shutdown source when not visible and Refresh browser when scene becomes active. Overlays reconnect on their own and restyle live when you save settings in a panel. If a re-upload doesn't repaint, right-click the source → Interact → Ctrl+Shift+R.

No authentication

Every endpoint above is open to anyone who can reach the port — that's what makes bots one-line simple. Keep HexCast on a trusted LAN and never expose it to the internet.
